# 猫国六边形像素地图：构建方案与讨论稿

状态：**首版可玩地图界面已接入本地游戏**。双击 `start.cmd` 默认进入地图版；独立画风 Demo 继续保留。以下设计讨论作为后续路线参考，具体已实现内容以[地图版使用与实现说明](地图版使用与实现说明.md)为准。

本次完成真实经济展示、地区建造与设施管理、科技目标、职业、材料加工、地图存档、相邻扩地与地形规划。当前按新需求改为同类多地块、每格默认 10 个槽位、逐座拆除与历史成本返还，旧存档自动迁移；邻接产量加成、运输模拟、战争和多文明仍待后续讨论。高级宗教、贸易、太空、政策和挑战使用同页的原版界面。

## 1. 我建议做成怎样的游戏

以“猫咪文明在谷地中成长”为视觉主题，采用俯视角像素画、六边形地形、聚落建筑群和少量猫咪活动动画。沿用现有实时资源经营节奏，让地图成为主要操作界面。

玩家能看到自己的田地、林业、矿区和居住区逐渐长出来；研究新科技时，地图提示哪里能升级、为什么值得升级。土地逐步探索，村庄从营火营地发展成城镇，再进入工业和太空阶段。

建议借鉴文明类游戏的六角布局、地形辨识、区域规划和探索感。回合制、军队战争、多国家 AI 属于另外一组玩法，可以在未来单独讨论。当前最值得先解决的是：**让发展可见，让升级有空间位置，让下一步目标更清晰。**

## 2. 三种构建方式，以及我的推荐

| 方式 | 玩家感受到的变化 | 对现有游戏的影响 | 建议 |
| --- | --- | --- | --- |
| A. 聚落可视化 | 原版建筑和数量显示成地图上的建筑群，点击地块管理 | 主要改变表现和操作入口 | 第一阶段先做，便于验证画风和接入 |
| B. 轻量地块经营 | 地形决定可建内容，邻接、扩地和少量区位加成提供规划价值 | 需要调整部分规则、存档与平衡 | 推荐作为逐步发展的正式方向 |
| C. 完整六角文明策略 | 城市、边界、单位、战争、多个文明、外交与回合 | 大幅重写游戏循环和经济 | 作为未来独立方向评估 |

**推荐路径：先完成 A，再从 B 中挑少数最有价值的机制。** 这样能保留现有内容深度，同时避免在画风还没确认前重做所有经济规则。

## 3. 一个地块应该代表什么

不建议长期坚持“一块地只能对应一座原版建筑”。原版后期建筑数量很大，这种规则会迫使玩家在地图上摆几百、几千次。

建议一个六边形代表一个**地区或建筑群**：

| 地块类别 | 可展示的内容 | 怎样兼容大量原版建筑 |
| --- | --- | --- |
| 农业区 | 田垄、猫薄荷、栅栏、小风车 | 一格容纳多块原版田地，数量增加时改变密度和外观 |
| 居住区 | 小屋、木屋、宅邸、道路与院落 | 若干房屋组成一个街区，显示该区汇总数量 |
| 林业区 | 森林、木料堆、伐木棚、锯木厂 | 按发展阶段替换或增添视觉元素 |
| 矿业区 | 矿口、采石场、矿车 | 汇总矿井等数量，保留开启/关闭管理 |
| 学术区 | 图书馆、学院、天文台 | 科技推进时逐步出现新建筑和装饰 |
| 宗教区 | 寺庙、祭坛、独角兽相关景观 | 保留宗教独立资源，表现长期成长 |
| 工业区 | 冶炼厂、工厂、烟囱、管线 | 区分设施数量与实际开启数量 |
| 沿岸区 | 港口、码头、船只 | 船只规模用若干代表性船影和数量显示 |

选择地块后打开侧栏，里面管理真实建筑数量和升级。地图负责清晰表达规模，而不是为每一份原版数量创建一个独立可点击对象。

开局少量建筑可以逐座展示，等数量增大后自然转成建筑群。若玩家不想手动规划，提供自动安排和重新整理布局。

## 4. 地形应该怎样参与玩法

建议先准备草地、森林、丘陵/山地、水域、未探索地五类。第一版视觉接入时，只做地形展示与区域安排；随后再决定哪些规则真正进入经济。

进入轻量地块经营阶段后，可考虑：

- 草地适合农业和居住。
- 林地适合林业；开发或保留森林可以成为选择。
- 山地适合矿业，沿岸适合港口。
- 聚落边界向外连续扩展，避免随意在远处跳着占地。
- 预设出生区域包含基本粮食、林木、矿点和可达水域，避免随机地图把关键科技卡死。

邻接加成可以增强规划感，但建议后加，并做到效果可见、幅度有限、有收益递减。比如学术区靠近聚落中心、港口连接贸易区时，清楚显示加成来源。具体幅度需要试玩后讨论。

道路第一阶段只负责连接感和猫咪动画。运输距离、物流堵塞、真实搬运等规则一旦引入，就会改变整个生产模型，应单独评估。

## 5. 怎样让科技升级不再让人发晕

把前一份科技路线文档的“目标 → 科技 → 建设”变成地图上的反馈：

| 当前目标 | 地图上的提示 | 点击后告诉玩家什么 |
| --- | --- | --- |
| 冬天供粮不足 | 农业区出现粮食缺口提示 | 农民、牧场、水渠分别如何帮助 |
| 科学容量不够 | 学术区高亮 | 缺多少容量，哪些建筑可以补足 |
| 研究采矿后 | 可安排的矿业区域高亮 | 建矿井、安排矿工、攒工坊原料 |
| 研究建筑后 | 居住区、仓储、林业升级提示 | 木屋、仓库和锯木厂各解决什么问题 |
| 研究导航学后 | 沿岸区域提示新内容 | 港口、船只、贸易需要的材料 |
| 研究新工业科技后 | 工业区显示可升级标记 | 原料和能源能否支撑新设施 |

建议主界面只追踪一个发展目标，例如“让科学容量达到下一项科技的要求”。玩家仍能自由研究，但能随时看到自己下一步为什么这么做。

科研节点还应分清：可研究、已研究、已解锁但材料不足、尚缺前置。研究完成时，地图给出简短反馈，并提供“查看新建设”的入口。

## 6. 画风与美术约定

当前建议是 **温暖、安静、可爱中带一点古老文明的神秘感**。

- 默认采用可调的斜俯视，六角地面带轻微厚度；提供俯仰和左右旋转，便于比较地形与建筑的空间关系。
- 草地用低饱和绿，屋顶用陶红，科研建筑用蓝灰，作物和营火用暖金色。
- 自然地形有明确轮廓，建筑比地面更醒目；避免过密地面噪点抢走建筑的注意力。
- 地图素材保持像素边缘，界面文字正常清晰渲染，不把中文做成难读的细小像素字。
- 小猫用简单小精灵，在建筑之间活动；营火、烟、四季变化增加生命感。
- 冬季体现地面、树冠和屋顶的积雪；界面同时标明季节，避免只靠颜色传递信息。

当前 Demo 的基础六角地块约 **48×56 像素**，建筑和角色采用同一像素尺度。正式素材可按统一图集制作，保持相同朝向、光照、阴影和地面接触点。小猫动画、建筑阶段与季节覆盖层分别制作，避免每种组合都画一整套。

先确认地块大小和建筑可读性，再批量制作素材。Demo 的图形由本地绘图代码生成，用于讨论风格；正式美术可以逐步替换。

## 7. 交互布局建议

桌面：顶部资源和季节 → 中间地图 → 右侧地块详情 → 底部任务/科技入口。

小窗口：地图优先，地块详情放在下面或作为可收起面板。主地图需要支持缩放、拖动和回到聚落中心；选中与悬停使用不同提示，建筑和地形都能键盘选择。

正式建筑操作建议这样走：选择地块 → 选区域或建筑 → 显示费用、地形条件和预期效果 → 建造 → 更新区域外观。常用建筑可以连续建设，数量大时使用批量操作。

镜头较远时显示地区轮廓和少量代表建筑，拉近后才显示道路、猫咪和装饰。文字标签避免全图常驻，优先显示选中区和当前目标。

## 8. 怎样与现有代码接起来

现有 `game/game.js` 及各管理器继续负责真实经济计算。地图增加独立的数据、渲染与操作适配层。

```text
现有游戏状态：资源、建筑数量、科技、职业、季节
                     ↓ 读取
                 地图适配层
                     ↓
          区域外观、地块信息、目标提示

玩家在地图发出建造/升级指令
                     ↓
          使用原版购买、校验和扣费流程
                     ↓
           原版状态更新 → 地图重新同步
```

不要由地图另算一份独立的粮食和科学，也不要直接给建筑 `val` 加一绕过原版费用和解锁逻辑。

第一阶段可以先只读接入建筑数量和季节；随后选少数建筑接入真实操作。工业设施还需要同步 `on` 等开启数量；建筑阶段变化也应反映在地图上。

技术上先用本地 **Canvas 2D + 原生 JavaScript** 即可。当前已经有静态文件服务，不必为原型引入新的运行依赖。将坐标、地图数据、绘图和原版适配分开，后面真遇到大量地块或动画的性能问题，再依据测量结果考虑其他渲染方式。

## 9. 地图数据与存档

正式地图至少记录：格式版本、地图种子/固定布局版本、地块坐标、地形、探索状态、地区归属、建筑群的分配关系。采用轴向六角坐标 `q/r`，便于查找六个邻居和计算距离。

建议将地图扩展作为同一个存档内的附加字段，例如 `hexMap`，与原版数据一同写入当前磁盘存档。原版管理器不会自动替新增字段完成保存和加载，需要适配层显式接入。

应有以下约束：

1. 没有地图字段的旧存档，首次进入时生成兼容布局。
2. 地图布局不能改变旧存档的已有资源与建筑总数。
3. 区域分配数量与原版建筑数量一致，避免双算产出。
4. 地图与经济状态一起保存、一起备份、一起恢复。
5. 卖出、升级阶段、转生时，明确处理对应地区与布局。
6. 原版数量大到地图装不下时自动聚合，不要求玩家清掉原建筑。

地图扩展目前为 `hexMap.version=2`，支持每格独立数量和建造成本；地形继续采用原固定地图，地图扩展写入原存档的 `hexMap`；具体字段、迁移与恢复规则见使用说明。迁移、数量守恒和原版保存/加载往返已加入自动验证。

## 10. 建议分四步构建

| 阶段 | 交付内容 | 验收重点 |
| --- | --- | --- |
| 0：画风原型（已完成） | 小地图、基础建筑、选格、季节、示意摆放 | 六角和像素风是否喜欢，建筑是否清楚 |
| 1：真实聚落展示（已完成） | 读取原版建筑、科技、季节，显示聚落成长 | 地图与原版数量一致，旧存档可加载 |
| 2：地图操作（已完成首版） | 地图建造、职业/设施管理、科技目标提示、布局保存 | 正确扣费、解锁检查、刷新和恢复；高级系统继续使用原版界面 |
| 3：轻量地图规则（部分完成） | 已有探索、相邻扩地、地形与区域限制；邻接机制尚未加入 | 当前扩地和迁移免费，不改变生产公式 |

每一步完成后再决定下一步。第一轮正式接入可以只覆盖田地、小屋、图书馆、矿井和工坊，既包含食物、人口、科学、矿物与加工，也容易验证成长感。

## 11. 当前 Demo 怎么看

启动方式：双击项目根目录 **start-map-demo.cmd**，或者直接打开 [地图 Demo](../game/hex-demo/index.html)。它是独立本地页面，不需要先启动原版服务。

若原版本地服务已经运行，也可以打开：`http://127.0.0.1:8765/hex-demo/index.html`。

当前包含：

- 半径 4、共 61 个六边形，固定地形布局和稳定装饰。
- 草地、林地、山地、水域、少量迷雾；初始 10 处建筑/景观。
- 营火、小屋、田地、图书馆、伐木站、采石场、遗迹和示意木桥。
- 点击或用方向键选择，查看地块说明。
- 可调视角：俯仰 30°～90°（90°为垂直俯视）、左右旋转 -180°～180°；提供斜俯视、近等距、垂直俯视预设。
- 在空草地试放田地、小屋或图书馆。
- 四季配色、积雪覆盖、猫咪活动、营火与烟雾。
- 六角网格和猫咪显示开关；支持减少动态效果的系统偏好。

刷新或点击“还原示例地图”恢复初始摆放。地形是固定示例，建筑摆放只保留在内存；迷雾、道路与桥梁用于展示外观，尚无探索、寻路、运输和经济规则。四季切换只改变画面。

视角采用 2.5D 正交投影：地形、道路和田地随相机倾斜、旋转，建筑、树木和猫咪作为直立像素精灵按屏幕深度排列。鼠标位置会通过逆投影换算回原六角地块，方向键按当前屏幕方向选邻格。调整视角不改变地图数据；“还原示例地图”保留当前视角，刷新恢复默认俯仰 45°、旋转 -20°。目前建筑使用单面精灵，不会因旋转露出真实的另一侧；若需要完整环绕观察，后续可采用多朝向素材或立体模型。

## 12. 我们下一轮最值得讨论的选择

| 讨论点 | 我的初步建议 | 另一种可选方向 |
| --- | --- | --- |
| 氛围 | 温暖森林猫村，逐步出现古文明元素 | 更严肃的文明史、荒野生存或蒸汽工业风 |
| 空间单位 | 一个六角是地区，可容纳多个同类建筑 | 每格一座建筑，玩法更强调土地稀缺 |
| 地形影响 | 先视觉接入，再加少量明确规则 | 从一开始就让地形决定生产和资源分布 |
| 时间节奏 | 保持现有实时经营，提供暂停管理 | 改为回合制，需要另做经济和事件节奏 |
| 探索 | 聚落附近逐步扩展，有遗迹和特殊地点 | 开局即可看到整张地图，自由规划 |
| 猫咪表现 | 少量代表角色，体现岗位和活动 | 每只猫独立寻路搬运，模拟规模更大 |

本次保持温暖森林猫村画风，地区模型已从无限聚合调整为独立多地块与容量限制；上文的无限聚合方案作为早期设计参考，当前规则以使用说明为准。下一轮可重点讨论目标提示是否足够清晰、是否需要更多地图面积，以及邻接机制是否值得改变现有经济。
